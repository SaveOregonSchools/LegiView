Help and Data Sources

LegiView is a local, provenance-first archive for Oregon bills, resolutions, and memorials. It provides durable historical inventory, explicit completeness, and a separately started archive downloader without destructive mirroring.

Historical Inventory and Archive Download

  1. Resolve and select official sessions.

    Inventory Backfill scans the complete official LegislativeSessions catalogue, shows older unsupported sessions, and lets you choose an inclusive supported range using official chronology.

  2. Build the inventory.

    The durable run catalogs supported Oregon measure types, reconciles OData and required OLIS displays, records anomalies and explicit completeness, and never silently downloads payloads.

  3. Review completeness.

    Session Status shows document-kind totals, source anomalies, probe totals, failures, and last successful activity.

  4. Preview and start downloads separately.

    Download Archive freezes selected sessions, kinds, statuses, and a creation-time cutoff. Known pending bytes are checked against the free-space floor.

Collecting a Measure

  1. Choose the official session and measure.

    Enter a session key such as 2026R1 and an identifier such as SB1501, HJR11, or SCR1.

  2. Follow the durable run.

    The run detail page shows explicit stages from session/reference loading through discovery, download, and finalization.

  3. Review the archived measure.

    Measure detail separates chief and regular sponsors and groups testimony, presentations, floor letters, and other committee documents.

  4. Retry only what failed.

    Completed files that still exist and validate are skipped; retry does not require recollecting the entire measure.

Runs, Restarts, and Retry

Collection and downloading happen in bounded background workers, not inside the browser request. Run state, current stage, counters, work items, and errors are persisted. If the process stops, work that had been active is normalized to an interrupted state rather than left falsely running.

Use Run History to inspect progress. Use Retry Failures for retryable HTTP failures, interrupted downloads, low-space pauses after space is restored, or files later found missing locally.

Archive Layout and File Safety

Example<archive_root>/2026R1/SB1501/public_testimony/244133/document.pdf
  • Downloads stream into a .part staging file and are atomically finalized only after validation.
  • Every completed payload records byte count, MIME information, SHA-256, and a relative archive path.
  • A changed payload is retained as another document version; earlier bytes are not silently overwritten.
  • Filenames and paths are sanitized for Windows and registered before any local open/reveal action.
  • LegiView does not execute downloaded content. Treat every PDF or Office file as untrusted.

Official Sources and Acceptable Use

Oregon Legislature OData is the preferred structured source. LegiView requests only known OLIS testimony pages where the displayed document list or historical presentation context must be reconciled. It is not a general-purpose crawler.

Settings Guidance

Archive root
Choose a durable location with enough capacity, normally outside this Git repository.
Request timeout
Maximum time for a source request before it becomes a recorded failure.
Maximum OData workers
Keep this upper bound low; dependency-ordered ingestion may use fewer, and filtered incremental requests are more important than parallelism.
Download workers
Controls bounded file acquisition. The default is intentionally conservative.
HTML concurrency
Applies only to known OLIS pages needed for testimony reconciliation.
Free-space floor
Configured in GB (5 GB by default) and converted to bytes for the downloader. It prevents a new transfer from consuming capacity reserved for the system.
Inter-request delay
Adds pacing between source requests and complements server-directed Retry-After.
Open settings

Phase 2 Boundaries

Phase 2 does not schedule recurring syncs, operate sist2, run OCR or semantic analysis, scan payloads for malware, add cloud/multi-user hosting, or destructively mirror source removals. Files remain ordinary readable payloads under one archive root for separately managed search tooling.
